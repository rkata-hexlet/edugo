## Что понял за сессию
- (18.10, автономная полировка) Рецензенты полезнее всего по картинке, а не по коду: контактные листы
  всех кадров (headless Chrome `?capture` + montage) — каждая проверка роли ловила реальные дефекты.
- Цепочка текстов scriptwriter → tech-writer → tech-expert снова окупилась: tech-expert поймал «номер
  захвата» (подсказывает fencing token), «ключ не даёт письму уйти дважды» (писем два, гасит получатель),
  at-least-once без «письмо терять нельзя».
- Эффекты движения — новым ключом узла (`World.frame` в ключе); при перемотке новым узлам нужно
  `animation: none` навсегда, иначе анимация стартует при снятии `.no-anim`.
- Офлайн-рендер: перед сменой кадра доводить анимации прошлого кадра (`finish`), иначе перемотка нового
  откатит их; рендер — со своей сборки (`vite preview`), dev-сервер перезагружает страницу при правках.
- Сетевой голос Chrome (Google русский) идёт мимо вкладки: ни захват вкладки, ни OfflineAudioContext его
  не пишут — только звук системы с живого экрана.
- Порядок работы над текстом, который держит качество: черновик (scriptwriter) → стиль (tech-writer) →
  смысл (tech-expert) → восприятие (learning-designer). Перестановка «стиль после смысла» каждый раз
  ломала смысл (кадры 9, 14, 20 эпизода 01) — смысл проверять последним.
- Пользователь проверяет эпизод «заходит или нет», а не разбирает: замечания вида «непонятно» —
  почти всегда пропущенная причинная связь в голосе (порядок событий, «почему это не улучшение»,
  местоимение без опоры). Чинить фразой с явной причиной, а не новым элементом экрана.
- Абстракции (время, срок, токен, «проверил и уснул») заходят, только когда у каждой есть видимый
  носитель в кадре; голос без носителя — «не заходит».
- Подбрасывать порог теста под каждую правку — плохо: длину решает пользователь, тест — страховка.
- /code-review ловит то, что тесты не видят (зависание плеера, наложения в кадре, «сцена врёт» в
  SQL-панели) — гонять перед каждым коммитом крупной правки.
- Сюжет держит **работа**, а не получатель: с клиентом/дверями норма и дубль выглядели одинаково.
  Дубль эффекта не виден в tasks (оба UPDATE пишут одну строку) — нужен приёмник вне таблицы.
- Дубли в кейсе 1 убирает `WHERE status='new'` под замком (CAS / FOR UPDATE), SKIP LOCKED — только
  скорость. Табло «без дублей / без ожидания» делает это видимым без подписей.
- `stuck` = застряла **без срока**: задача с талоном у зависшего пода ограничена сроком — не застряла.
- Рецензент может противоречить сам себе: правку tech-expert сверять с моделью/тестом и его прошлыми
  выводами (кадр 20 эпизода 01: «C ждёт на #2» — оказалось неверно, модель была права).
- Тест после крупной правки — по смыслу кадров (поиск по событиям), а не по номерам: склейки их сдвигают.
- 18.10 машина зависла: vitest дорос до 5.7 ГБ (бесконечный цикл в промежуточной правке) — с тех пор
  потолок кучи воркера 512 МБ в `vitest.config.ts`.
- `FOR UPDATE … LIMIT 1` после ожидания не «возвращает пусто», а берёт следующего кандидата из
  снимка; строка, переставшая подходить, остаётся заблокированной ждавшим (отсюда «конвой»:
  C ждёт уже B). Сначала смоделировал неверно — поймал tech-expert, теперь держит тест.
- При падении пода Postgres сам снимает блокировки; lease нужен из-за цены долгой транзакции и
  зависших живых воркеров. Владелец — токен захвата, не имя пода.
- Звук сравнением соседних кадров хрупок (сброс сцены внутри акта, кадр 0, «залипший» affected) —
  поэтому журнал событий в модели. Агенты, созданные посреди сессии, по имени не подхватываются:
  запускаю general-purpose с ролью из файла и явной моделью.
- Сценарий сначала через tech-expert, потом scriptwriter (с его вводными), и только потом MVP —
  иначе первый показ уходит на правки, которые делаются на бумаге.
- Ценность продукта — показать гонку во времени, которую текстом не видно. Каждый эпизод по шаблону:
  хук → нормальный мир → поломка → наивный фикс → решение → твист → шпаргалка.
