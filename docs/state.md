## Что понял за сессию
- Расход токенов, 27.10 (логи 21 сессии): ~80% — главная сессия, агенты ~20%. Дорого не само действие, а ход
  на большом контексте: медиана 194k, сессии по 300–700 ходов, `/clear` почти не делали; глобальный
  `autoCompactWindow` 400k давал контексту расти. Запись кэша (TTL 1 ч) — ещё ~15%: после паузы весь контекст
  пишется заново. Отсюда правила «Экономия токенов» в CLAUDE.md; эффект смотреть `npm run tokens` через неделю.
- Эхо комнаты в дублях (27.10): эквалайзер (срез 250–500 Гц) и экспандер пауз (−3…−19 дБ между словами по замеру)
  на слух пользователя ничего не изменили — «оставь как есть». Если вернёмся: нейросетевой dereverb (DeepFilterNet,
  ~1 ГБ PyTorch на CPU) или запись ближе к микрофону; ffmpeg-фильтры не повторять.
- git worktree с `node_modules`-ссылкой на основную папку: `.gitignore` с `node_modules/` (со слэшем) ссылку не
  ловит — она уехала в `master` коммитом kit, а слияние в ветку подменило ею настоящую папку. Теперь `node_modules`
  без слэша; `npm run ep` ставит зависимости в папку эпизода (`npm ci`), ссылок не делает.
- `git branch -d` сверяет влитость с текущей веткой, а не с `master`: ветку kit/tools проверять
  `git merge-base --is-ancestor <ветка> master`, потом `-D`.
- 29.10 `vitest run --root /` (временный тест из scratchpad) обошёл всю ФС и повесил ноутбук — запрет в `.claude/guard.txt`.
  Временный тест — файлом внутри `src/`, потом удалить. Перезагрузка чистит `/tmp`: worktree в scratchpad остаётся
  записью и держит ветку (`master` «уже открыт») — `git worktree prune`.
- Эпизод 09, 25.10: tech-expert ловит противоречие числа в голосе и часов в модели («больше двух часов» при 06:00) —
  любое время в голосе сверять с `advance` в кадре. Его же формулировка в следующем круге оказалась слишком
  категоричной («не узнает» вместо «не сразу»): итоговая сверка нужна и для правок самих рецензентов.
- Число в голосе без носителя не заходит: метка скачка часов (`+1 мин / +2 ч / +20 с` из события `tick`) — дешёвый
  общий носитель, кандидат в kit.
- Порядок колонок табло держать одинаковым во всех кейсах эпизода: переставленные лампы «прыгают» (learning-designer).
- Эпизод 08, 24.10: где в кадре несколько звеньев системы, «чья это база» решает раскладка, а не голос: персонаж базы
  отдельно от таблиц (шапка) читается как чужой сервис — БД рисовать рамкой вокруг своих таблиц, внешнее — пунктиром.
- `fx-fade` анимирует opacity до 1 и затирает `opacity` атрибута — полупрозрачной маске класс не давать.
- Голос, который ведёт по коду или системе («сначала… потом…»), — нарезать кадрами по фразам; пометки разом
  learning-designer и motion-designer ловят оба. Рецензенты разных ролей сходятся в одном: плотный ключевой кадр
  лечится нарезкой, текст при этом можно не трогать.
- Токен прошлого эпизода во вставке (`7f3a` из 01) спутался с ключом этого (`k-7f3a`) — идентификаторы эпизодов не
  повторять.
- Эпизод 07, 24.10: learning-designer нашёл главные риски в самых плотных кадрах (пик, развязка, ключевой приём) —
  лечится разрезкой кадра на две мысли, а не подсветкой по фразам (плеер даёт один фокус на кадр). Разрезка ломает
  «рифму в одном кадре» звука — рифму держит одинаковый старт цепочки «так → пинг → бзз», а не весь хвост.
- `npm run narration` без `--scene` выгружает эпизод 01, а не текущий: всегда `-- --scene NN-имя`.
- Эпизод 06 принят с первого показа (24.10). Сработало: чек-лист повторяющихся ошибок подачи до сценария
  (`docs/reviews/06-recurring-mistakes.md`) и полный круг «learning-designer → tech-writer → tech-expert» ещё раз после
  каждой крупной правки, а не один раз.
- Эпизод 06, 24.10: tech-expert после learning-designer снова поймал неправду, которую принесла правка подачи
  («SERIALIZABLE закрывает все пути» — путь без своей проверки ломает правило и на нём). Цепочка «подача → стиль →
  смысл» нужна на каждом круге, не только на первом.
- Учебный код с `_` вместо ошибок врёт, как только ошибка может прийти не там, где пометка: на SERIALIZABLE 40001 бывает
  на любом запросе, и pgx на Commit тогда вернёт ErrTxCommitRollback. Окно кода 05 — фиксированной высоты, `drawCode`
  теперь берёт число строк эпизода.
- Звук: зажим `at` по окну 0,45 с схлопывал «бзз-бзз-стон» в одну точку — окно держат смещения рецепта, а не зажим.
- Эпизод 04, 23.10 (пять версий объяснения HLL за сессию): пользователю «заходит» объяснение, где **каждый шаг служит
  одному вопросу зрителя** («сколько уникальных?»), а не устройство механизма; глубина вторична — v3 с честным
  опытом показалась перебором, v5 той же глубины с целью и монеткой — понравилась. Рецензенты по кадрам этого не видят:
  спрашивать их «какой вопрос зрителя держит блок».
- Headless Chrome иногда снимает белый кадр (страница не успела) — переснимать по одному; размер PNG < 30 КБ — признак.
- Табло kit на 490 px: заголовки критериев длиннее ~10 знаков слипаются при `lampX` [285, 420] — в 03 [258, 416],
  имя попытки ≤ ~20 знаков.
- `scripts/voice.mjs` без `--scene` (и с любыми другими аргументами) переобрабатывает **все** дубли: 21.10 я так
  запустил его случайно. Длины совпали, файлы вернул копией из `dist/voice`. Сам файл `.ogg` между прогонами
  отличается байтами (серийный номер потока Ogg), длина — нет.
- learning-designer ловит расхождение голоса и картинки только по снимкам: «короткий TTL бьёт по базе» на кадре
  с одной горячей ссылкой — неправда картинки, хотя голос технически верен. Цена — фраза-уступка в голосе.
- Итог повтором конца акта показывает итог, а не механизм; повторять надо узнаваемый момент (команды/стрелки).
- Dev-сервер Vite знает файлы `public/` на момент старта (а `public/voice` ещё и исключён из слежения,
  чтобы суфлёр не перезагружался): новые дубли раздаёт сам плагин `/voice/…`, иначе на них приходит index.html.
- Поддельный микрофон headless Chrome (`--use-fake-device-for-media-stream`) пищит — так суфлёр
  проверяется целиком без пользователя.
- Длина субтитра — проблема вёрстки, а не текста: резать текст под экран — плохо (рвёт рассказ,
  пользователь), показывать кусками по паузам — хорошо. Одна строка в записи ≈ 65 знаков (2.1cqw).
- Голос Chrome: `onstart` у каждой utterance приходит — по нему можно синхронизировать субтитр.
- Цепочка текстов scriptwriter → tech-writer → tech-expert снова окупилась: tech-expert поймал «номер
  захвата» (подсказывает fencing token), «ключ не даёт письму уйти дважды» (писем два, гасит получатель),
  at-least-once без «письмо терять нельзя».
- Эффекты движения — новым ключом узла (`World.frame` в ключе); при перемотке новым узлам нужно
  `animation: none` навсегда, иначе анимация стартует при снятии `.no-anim`.
- Офлайн-рендер: перед сменой кадра доводить анимации прошлого кадра (`finish`), иначе перемотка нового
  откатит их; рендер — со своей сборки (`vite preview`), dev-сервер перезагружает страницу при правках.
- Сетевой голос Chrome (Google русский) идёт мимо вкладки: ни захват вкладки, ни OfflineAudioContext его
  не пишут — только звук системы с живого экрана.
- Подбрасывать порог теста под каждую правку — плохо: длину решает пользователь, тест — страховка.
- /code-review ловит то, что тесты не видят (зависание плеера, наложения в кадре, «сцена врёт» в
  SQL-панели) — гонять перед каждым коммитом крупной правки.
- Рецензент может противоречить сам себе: правку tech-expert сверять с моделью/тестом и его прошлыми
  выводами (кадр 20 эпизода 01: «C ждёт на #2» — оказалось неверно, модель была права).
- Тест после крупной правки — по смыслу кадров (поиск по событиям), а не по номерам: склейки их сдвигают.
- 18.10 машина зависла: vitest дорос до 5.7 ГБ (бесконечный цикл в промежуточной правке) — с тех пор
  потолок кучи воркера 512 МБ в `vitest.config.ts`.
- Звук сравнением соседних кадров хрупок (сброс сцены внутри акта, кадр 0, «залипший» affected) —
  поэтому журнал событий в модели. Агенты, созданные посреди сессии, по имени не подхватываются:
  запускаю general-purpose с ролью из файла и явной моделью.
- Сценарий сначала через tech-expert, потом scriptwriter (с его вводными), и только потом MVP —
  иначе первый показ уходит на правки, которые делаются на бумаге.
- Ценность продукта — показать гонку во времени, которую текстом не видно. Каждый эпизод по шаблону:
  хук → нормальный мир → поломка → наивный фикс → решение → твист → шпаргалка.
