# Запись эпизода в mp4

Эпизод живёт в своей ветке; писать и рендерить его — в его папке (раздел 3), ветку основной папки не переключая.

Кадры и звуки — из той же сцены, что и плеер; голос — дубли диктора.

## 1. Офлайн-рендер — `npm run render` (без экрана, детерминированно)
```
npm run dev                       # в соседнем терминале (http://localhost:5173)
npm run render                    # → out/episode-01.mp4 (+ out/episode-01.wav — звуки событий)
npm run render -- --from 60 --to 90 --out /tmp/cut.mp4   # кусок для проверки
```
- headless Chrome (`/usr/bin/google-chrome`, другой — `--chrome` или `CHROME=`) открывает
  `?capture&render`, скрипт перематывает шкалу записи кадр за кадром (`window.__edugo.seek(t)`):
  CSS-анимации и переходы ставятся на паузу в нужной точке, так что движение в ролике то же, что в плеере.
- Шкала: заставка 2.5 с → кадры (время кадра = дольше из `hold` и голоса диктора: длина дубля, а без
  дубля — расчётный темп 2.5 слова/с) → финальная карточка: не меньше 4 с и не меньше вывода голосом
  (`engine/timeline.ts`).
- Звук — `OfflineAudioContext` той же страницы по той же карте звуков (`sound.ts`), громкость
  подтянута `loudnorm`. Видео и звук идут от одной шкалы — синхронны по построению.
- Голос — дубли диктора (раздел 2); кадр без дубля идёт молча по расчётному темпу. Субтитров
  в ролике нет (решение пользователя 21.10); в плеере — по CC.
- Скорость ~17 кадров/с на 1920×1080 → полный эпизод (~10 мин) рендерится ~18 мин.

## 2. Голос диктора — суфлёр (ADR-0004)
1. `npm run dev`, открыть `http://localhost:5173/?record`, разрешить микрофон.
2. Читать текст под кадром. **Пробел** — дубль сохранён, сразу пишется следующий кадр;
   **Backspace** — прочитать кадр заново; **Esc** — пауза; **←/→** — другой кадр; **P** — прослушать дубль.
   Стрелки и P во время записи сами ставят паузу (недочитанный кадр не сохраняется): записал кадр → **←**, **P** —
   слышишь только что записанное.
3. Суфлёр начинает с первого кадра без дубля: после правки закадра — сразу с устаревших.
   **Переписать кадр**: номер в адресе (`#step=N`, страница не перезагружается) или ←/→, пробел — читать,
   пробел — сохранить. Если у следующего кадра дубль уже есть, суфлёр встаёт на паузу на переписанном.
- Дубль, где голос занял меньше 30 % записи, сервер не принимает («голос почти не слышен»).
  Прежний удачный дубль кадра при этом остаётся (и сырой, и обработанный); отвергнутый лежит рядом —
  `voice/<сцена>/<ключ>.rejected.webm`, для разбора, в обработку не идёт.
- Звук чистит dev-сервер (`scripts/voice.mjs`): щелчки клавиши, тишина по краям, гул, шум, громкость.
  Поменяли фильтры — `npm run voice` переобработает все сырые дубли из `voice/`.
  Дубль, не прошедший проверку с новыми фильтрами, сохраняет прежний файл и длину; список таких — в конце
  вывода, код выхода 1.
- Полоска уровня под кадром краснеет при перегрузе — отодвинуться от микрофона.
- Дальше `npm run render`: голос попадает в mp4 сам, кадр длится по дублю.

## 2а. Телефон как микрофон (Android, scrcpy) — черновик, не проверено
Зачем: эхо комнаты фильтры `voice.mjs` не убирают (разбор 27.10), помогает только микрофон ближе ко рту.
Встроенный микрофон ноутбука далеко и слышит вентилятор; телефон в 15–20 см — нет.
Схема: `scrcpy` забирает микрофон телефона по USB без сжатия → PulseAudio делает из него виртуальный
микрофон «PhoneMic» → суфлёр пишет с него как с обычного (`recorder.ts` берёт микрофон по умолчанию).
Camo Studio не подходит — клиента под Linux нет; Bluetooth-гарнитура — звук как в звонке (16 кГц).

**Один раз**
1. Телефон: Android 11+. «О телефоне» → 7 раз «Номер сборки» → «Для разработчиков» → «Отладка по USB».
2. Подключить кабелем, на телефоне разрешить отладку; `adb devices` — телефон в списке со словом `device`.
3. `scrcpy` ≥ 2.0 (в apt Ubuntu 22.04 — 1.21, звук не умеет): `sudo snap install scrcpy` или сборка
   с github.com/Genymobile/scrcpy/releases. Проверить: `scrcpy --version`.

**Каждый сеанс записи**
```
# виртуальный микрофон (живёт до перезагрузки)
pactl load-module module-null-sink sink_name=phone sink_properties=device.description=PhoneSink
pactl load-module module-remap-source master=phone.monitor source_name=phonemic source_properties=device.description=PhoneMic
pactl set-default-source phonemic

# звук с телефона — держать запущенным, пока идёт запись
PULSE_SINK=phone scrcpy --no-video --no-control --audio-source=mic --audio-codec=raw
```
- Экран телефона не блокировать: на части прошивок заблокированный телефон отдаёт тишину.
- Телефон — сбоку ото рта в 15–20 см, микрофоном (низ корпуса) к себе: не дуть на «п», «б».
- Суфлёр `?record` как обычно (раздел 2); браузер спросит микрофон — выбрать PhoneMic.
- Вернуть встроенный: `pactl set-default-source <имя>` (список — `pactl list short sources`)
  или выгрузить модули: `pactl unload-module module-remap-source; pactl unload-module module-null-sink`.

**Первая проверка — до записи эпизода**
1. Полоска уровня в суфлёре шевелится от голоса → звук доходит.
2. Одну фразу записать встроенным и телефоном, послушать рядом (P в суфлёре или Audacity):
   меньше эха и шума в паузах — переходим на телефон; разницы нет — не возимся, думаем о USB-петличке.
3. Дубль с телефона прошёл проверку сервера (не «голос почти не слышен»), в плеере звучит без щелчков и обрывов.
Прижилось — оформить командой (`npm run mic`) и снять пометку «не проверено».

## 3. Эпизод в своей папке — `npm run ep -- NN`
```
npm run ep -- 02            # ветка episode/02-* → ../edugo-02, суфлёр http://localhost:5102/?scene=02&record
npm run ep -- 02 --play     # то же, плеер
npm run ep -- 02 --rm       # убрать папку (ветка остаётся; с незакоммиченным git откажет)
```
- Папка — git worktree: та же история, своя ветка. Первый запуск ставит зависимости (`npm ci`).
- Ветка уже открыта где-то (в основной папке тоже) — сервер стартует там, вторую копию не заводим.
- Порт `51NN` у каждого эпизода свой: можно держать два сервера сразу.
- Дубли (`voice/NN/`, `public/voice/NN/`) и mp4 (`npm run render -- --scene NN` в той же папке) коммитятся в ветку эпизода.
