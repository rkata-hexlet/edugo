# Эпизод 11 — «Где моя бронь?» (рабочее название)

Тема: чтения уходят на реплики, реплика отстаёт — гость не видит бронь, которую только что сделал, и бронирует второй раз.
Read-your-writes: primary после своей записи → ⟲ синхронная репликация `remote_apply` (цена) → метка LSN — решение. Мир — **сервис бронирования
отеля** из эпизода 10 (гость, рамка «Сервис бронирования» с подами, Postgres); поставщика в кадре нет. Ветка от `episode/10-timeouts`
(переиспользует сцену 10), выпуск после 10. Эпизод понятен без 10: отсылок к другим роликам нет.
Разборы: `docs/reviews/11-tech-expert-arc.md` (техническая основа, «не обещаем», числа), `docs/reviews/11-scriptwriter-arc.md`
(мир, носители, табло, заблуждения зрителя, **раскадровка v2 — 30 кадров**, пересобрана после приёмки MVP).
Закадр дословно — `docs/episodes/11-narration.md` (выгрузка из `script.ts`).

## Арка
Знакомство (мир сервиса до нажатия → бронь в Postgres → чтений много, все в одну базу → две реплики, «Postgres · primary» →
лента журнала WAL, которую primary отправляет репликам, streaming replication → два пула в коде Go) → норма (золотая карточка брони
проскакивает бегунки реплик за такт, «Мои брони» с бронью) → хук: распродажа, лаг 3 с, «Мои брони» пусто, гость жмёт ещё раз —
**две брони, хотя ничего не сломалось**.
- **Кейс 1 из 2 «Гость не видит свою бронь»** — табло «гость видит свою бронь / primary не перегружен»: читаем с реплик 🔴🟢 →
  всё с primary 🟢🔴 → ⟲ после своей записи — primary 2 с 🟢🟢. Цена фразой: чужие записи (подтверждение, другое устройство) так
  не ловятся; 2 с — угаданное число.
- **Кейс 2 из 2 «Отстаём дольше двух секунд»** — та же метка при лаге 3 и 5 с 🔴🟢: метка погасла раньше, чем реплика дошла
  (sticky на 30 с — фразой); гость попадает то на одну реплику, то на другую — бронь то есть, то нет (**Monotonic reads**, отдельный
  кадр, голос называет другой бедой) → ⟲ `remote_apply` 🔴🟢: механика (on ждёт запись на диск, видимость даёт только
  `remote_apply` и только на синхронной); синхронная одна, а читаем с обеих — со второй брони нет; цена картинкой — синхронная
  легла, COMMIT висит; «обе синхронные — ждём самую медленную» → ⟲ вернёмся: метка LSN — после COMMIT берём
  `pg_current_wal_lsn()`, перед чтением сверяем с `pg_last_wal_replay_lsn()` реплики; не догнала ни одна — primary 🟢🟢; что
  такое LSN — двумя фразами (адрес места на ленте, только растёт; у других баз свой аналог); мигания нет → граница: решения под
  запись («номер свободен?») — только primary (кадр «Свободен!» из прошлого). Кейс кончается решением (пользователь, 28.10).
- **Итог** — повтор образов: пустые «Мои брони», всё с primary, мигание, висящий COMMIT, билет с местом на ленте (последним).

Обложка: «Где моя бронь?» / «Реплика отстаёт на пару секунд, и гость бронирует номер дважды. Как показать человеку его
собственную запись?». Outro: «Реплика отвечает из прошлого».

Ярлыки: Read replica, Replication lag, Read-your-writes, Monotonic reads, Synchronous replication. Stale read, streaming
replication и LSN — голосом; walsender/walreceiver не называем (перегруз; пользователь, 28.10).
Не брать (tech-expert): Sticky session, Strong consistency / Linearizability, Causal consistency, Failover, Master/slave.

## Честность модели (держать в симуляции и голосе)
- Репликация асинхронная: COMMIT на primary реплику не ждёт. Лаг в норме миллисекунды, в хуке 3 с, вторая реплика в кейсе 2 — 5 с.
- Реплика не знает, что отстаёт: отвечает сразу и без ошибки по тому, что проиграла. Ни ⏳, ни «секунду». Рассказчик не говорит
  «пропала» — это только мысль гостя.
- Чтения на реплики разносит наш код (два пула), а не Postgres.
- LSN берём после COMMIT; метка в cookie не видна с другого устройства (по `user_id` на сервере — видна) — не обещаем.
- Верхней границы лага нет; «2 секунды хватит» не обещаем.
- `synchronous_commit = on` не даёт свежих чтений; `remote_apply` — только на репликах из `synchronous_standby_names`;
  асинхронная реплика рядом отстаёт по-прежнему, поэтому при чтении с обеих лампа «видит» красная.
Полный список «не обещаем» — разбор tech-expert, раздел «Что сцене можно утверждать».
