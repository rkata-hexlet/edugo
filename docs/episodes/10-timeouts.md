# Эпизод 10 — «Таймауты и повторы» (рабочее название)

Тема: внешний поставщик номеров начинает отвечать по 30 с. Таймаут, повторы (retry storm, ключ, backoff, jitter),
circuit breaker. Мир новый — **сервис бронирования отеля** (первый эпизод мира). Эпизод **самодостаточный**: отсылок к
другим роликам нет, ключ повтора — «наш номер брони» (решение пользователя 28.10: 08 и 03 ещё не выпущены).
Разборы: `docs/reviews/10-tech-expert-arc.md` (техническая основа), `docs/reviews/10-scriptwriter-arc.md` (мир, табло,
заблуждения зрителя, раскадровка v1 с закадром — 32 кадра).

Статус: **v0.2 (28.10) — MVP: 38 кадров серыми фигурами, закадр синтезом (`?scene=10`); фаза 1 — приёмка пользователем.** Развилки A–F решены (как рекомендовано).

## Арка
Знакомство (гость, поды, наша база с пулом соединений, поставщик — внешний мир; код брони на Go: вызов поставщика
**внутри транзакции**) → норма (поставщик отвечает за 200 мс) → хук: **поиск лёг из-за сервиса, к которому он даже не
ходит** — брони держат слоты пула, пока ждут поставщика, поиску слотов не осталось.
- **Кейс 1 из 3 «Поставщик тормозит. Выживет ли поиск?»** — табло «поиск отвечает / гость знает, что с бронью»:
  ждём сколько угодно 🔴🔴 → таймаут 3 с 🟡🟡 (поиск дышит, пока поток мал) → ⟲ вызов вне транзакции 🟢🟡
  (bulkhead — одной фразой голосом, без кадра; ярлыка у попытки нет). Сквозной вопрос «а бронь-то есть?»: мысль пода «Не вышло.», «?» у поставщика.
- **Кейс 2 из 3 «Не дождались ответа. Повторить?»** — табло «бронь одна / поставщик не добит». Открывается ответом:
  у поставщика строка `confirmed` — **не дождались ≠ не получилось**. Повторить сразу ×3 🔴🔴 (две брони + волна) →
  наш номер брони 🟢🔴 → exponential backoff 🟢🔴 (бьют снова вместе) → jitter 🟢🟡 (пик сглажен, повторов не меньше).
  Deadline — одной фразой.
- **Кейс 3 из 3 «Поставщик лёг на минуту. Сколько ещё стучаться?»** — табло «ответ сразу / брони снова идут»:
  повторы как было 🔴🔴 → breaker open 🟢·(пусто) → …open навсегда 🟢🔴 → half-open 🟢🟢. Рубильник у каждого пода свой,
  щёлкают не одновременно.
- **Итог** — повтор образов: забитый пул, строка `confirmed` после таймаута, волна повторов, рубильники.

Обложка: «Таймауты и повторы» / «Поставщик тормозит. Как не лечь вместе с ним и не добить его повторами?».
Outro: «Не дождались — не значит, что не получилось». Не обещаем: «бронь всегда пройдёт», «двух броней не будет никогда»,
«таймаут спасает от каскада» (tech-expert).

Ярлыки (проверены tech-expert): Timeout, Cascading failure, Retry storm, Idempotency key, Backoff · jitter, Circuit breaker,
Half-open, Bulkhead. Не брать: Thundering herd, Load shedding, Exactly-once, Metastable failure.

## Честность модели (держать в симуляции)
- Пул соединений с базой общий для поиска и брони; бронь держит слот, пока ждёт поставщика (в Go горутины не кончаются,
  у HTTP-клиента по умолчанию нет лимитов — носитель только пул базы).
- Таймаут отменяет наше ожидание, а не запрос: карточка остаётся в очереди поставщика, бронь у него появляется позже.
- Ключ — наш номер брони, поставщик должен уметь по нему узнавать повтор (умеет не каждый, хранит не вечно).
- Breaker — в памяти каждого пода; в отказы идут таймауты, 5xx, 429.

## Решения по развилкам (пользователь 28.10 — «как рекомендуешь»)
A. Последствие — первой фразой кадра 1, затем знакомство. B. «А бронь-то есть?» висит весь кейс 1, ответ — в начале
кейса 2. C. Одно «⟲ Иначе» (вызов вне транзакции); bulkhead — фразой. D. Backoff и jitter — две попытки. E. Кейс 3 через
«open навсегда» → half-open. F. Ярлыка у «вызова вне транзакции» нет, хватает голоса.
Раскадровку v1 из разбора scriptwriter при MVP править под C: кадр 17 (bulkhead) убрать, фразу — в кадр 16.
