## 30.10 — фаза 0: тема
- Тема выбрана пользователем: feature flags, мир отеля; ветка `episode/14-flags` от `episode/13-keyset`
  (выпуск по цепочке 10 → 11 → 12 → 13 → 14).
- Набросок арки (мой, до разборов) — фокус на механике, а не на практиках:
  - флаг в коде → без передеплоя: флаг в рантайме, под перечитывает раз в 30 с → поды расходятся, запросы гостя прыгают по подам;
  - процент через `rand()` — гость скачет между версиями → стабильно `hash(user_id) % 100`;
  - сервис флагов лёг → лежит оплата → локальный кэш + безопасный дефолт (рифма с 10);
  - кульминация: флаг откатили, а новый код уже записал брони в новом формате → старый падает; флаг откатывает код, не данные →
    expand/contract;
  - итог: забытый флаг переиспользовали — проснулся мёртвый код (класс аварий, Knight Capital 2012) — одной фразой.
- Риск: тема меньше про базу, чем серия; кейс 4 — краешком миграций, не уходить в отдельную тему.
- Разбор tech-expert — `docs/reviews/14-tech-expert-arc.md`: «сервис лёг → оплата лежит» — только у наивной схемы (запрос на каждый
  вызов), лечит локальная копия правил; кейсы 1 и 3 наброска слиты в «где живёт флаг»; данные кульминации A/B; факты Knight по приказу SEC.
- Данные кульминации — вариант A (`payment: at_hotel`, старая ветка отменяет бронь), мой выбор; пользователь может поменять на приёмке.
