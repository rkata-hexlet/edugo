# Эпизод 01 — «Почтальоны и одна посылка»

Тема: несколько подов разбирают общую очередь задач в Postgres (READ COMMITTED). Гонка →
условный UPDATE → `FOR UPDATE` → `SKIP LOCKED` → lease-талон → зомби-воркер, токен захвата
и идемпотентность у получателя.

Статус: **сценарий v2 (после tech-expert и scriptwriter), MVP собран — на обсуждении.**
MVP: `npm run dev` → http://localhost:5173 (кадр по ссылке: `#step=N`).

## Арка
Хук — провал из финала: «Оба курьера всё сделали правильно. Клиенту списали дважды». Ролик чинит
одно за другим, на SKIP LOCKED — ложный хэппи-энд, затем курьер зависает, и в финале мы у той же
двери: клиент «Уже получил, спасибо». Главный «ага»: **склад бережёт свою запись, а двойной
эффект ловит получатель.**

## Мир и персонажи
- Сортировочный цех. Стеллаж = таблица `tasks`, полка = строка (`id`, `status`, `claim_token`,
  `lease_until`).
- **Курьеры-гоферы A, B, C** = поды. B — неудачник эпизода: проигрывает толпу, стоит в конвое,
  зависает, становится зомби.
- **Кладовщик-слон Postgres** — ворчит, работает строго по правилам, никого не жалеет. Хвалит
  один раз за эпизод — на SKIP LOCKED.
- **Клиент у двери** — в хуке и в финале, один ракурс (рифма).
- **Табличка «READ COMMITTED»** на стене — во всех кадрах. **Настенные часы склада** — с акта 3.
- Правило подачи: картинка раньше термина (замок → FOR UPDATE, пожал плечами → SKIP LOCKED,
  талон → lease).

## Шпаргалка
```sql
-- захват (одним оператором, autocommit — now() = время БД)
UPDATE tasks
   SET status='in_progress', claim_token=gen_random_uuid(),
       attempts = attempts + 1, lease_until = now() + interval '30s'
 WHERE id IN (SELECT id FROM tasks
               WHERE (status='new' OR (status='in_progress' AND lease_until < now()))
                 AND attempts < 5
               ORDER BY id LIMIT 10
               FOR UPDATE SKIP LOCKED)
RETURNING id, claim_token;

-- завершение и продление — только по своему талону
UPDATE tasks SET status='done'                         WHERE id=$1 AND claim_token=$2;
UPDATE tasks SET lease_until = now() + interval '30s'  WHERE id=$1 AND claim_token=$2;
```
- индекс: частичный `ON tasks(id) WHERE status='new'` + индекс по `lease_until` для просроченных;
- heartbeat: долгая задача продлевает талон;
- `attempts ≥ 5` → полка возвратов (dead-letter);
- SKIP LOCKED — не строгий FIFO;
- эффекты — идемпотентны (ключ = id задачи); гарантия at-least-once.

Ответ на собесе: «Захват — одним `UPDATE … WHERE id IN (SELECT … FOR UPDATE SKIP LOCKED)` с
lease и токеном захвата; транзакцию на время работы не держим; завершение — по токену; побочные
эффекты идемпотентны, потому что доставка at-least-once».

## Технические оговорки (tech-expert)
- Всё в READ COMMITTED. Условный UPDATE после ожидания перепроверяет WHERE на новой версии строки.
- `FOR UPDATE … LIMIT 1` после ожидания не возвращает строку, переставшую подходить, и берёт
  следующего кандидата из того же снимка (поэтому «конвой», а не «ушёл ни с чем»).
- При падении пода с открытой транзакцией Postgres сам откатывает её и снимает блокировки — lease
  нужен из-за цены долгой транзакции и зависших живых подов, а не из-за падений.
- Владелец — токен захвата, не имя пода. Проверка токена бережёт только запись в БД.

## Ярлыки-термины (проверены tech-expert)
Рамка после хука: «Competing consumers: несколько подов, одна очередь. Как не сделать работу дважды?»

| акт | ярлык (с кадра, где механика уже видна) |
|---|---|
| 1 | Race condition · check-then-act |
| 2 | Local lock ≠ distributed lock |
| 3a | Compare-and-set · optimistic locking |
| 3b | Pessimistic locking |
| 3c | Non-blocking claim · SKIP LOCKED |
| 4 | Lease |
| 5 | At-least-once · idempotency key |

Шпаргалка — два кадра: запрос целиком + «Что мы прошли» (ярлык → одна строка расшифровки).
Отвергнуто: «fencing token» в акте 5 (у Клеппмана — монотонный номер, проверяемый внешним ресурсом;
у нас — CAS по токену владельца в той же БД, а дверь он как раз не защищает); «idempotency key →
at-least-once» (стрелка переворачивает причину); «без дублей» в рамке (финал показывает дубль
доставки, который гасит получатель).

гонки и финальная реплика кладовщика.
