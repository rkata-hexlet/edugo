## 29.10 — разбор MVP командой (пользователь: «подача так себе», «решаем потери, получаем производительность»)
Разборы: `docs/reviews/13-{scriptwriter,learning-designer,tech-expert}-mvp.md`. Сходятся:
- беда скорости OFFSET звучит только после победы закладки → «медленно» липнет к keyset; индекс появляется только у закладки
  (tech-expert: сравнение нечестное), кадр 16 заранее сеет «иначе не быстро»;
- одна шкала из трёх ламп «не пропало / не дважды / быстро» на весь эпизод; итоговая матрица OFFSET vs keyset;
- панель Postgres перегружена (~30 карточек): таблицу по id — один раз, дальше выдача пересобирается на глазах по нажатию;
- закадр ~1800 слов → ~1100; итог 6 кадров → 2–3; ⟲ снимок — одна фраза.
Технические правки при любой арке (tech-expert): `ORDER BY price, id` и в попытках `>`/`>=` (неполна закладка, не сортировка);
«всего страниц» — не цена закладки (COUNT нужен и OFFSET); назад листать закладка умеет, не умеет прыгать на N; кадр 9 —
обещание только для карточек, что стояли на месте; вставка позади закладки («Пирс») не увидится; выгрузка — закрытый период,
без «+3 новые в конец»; фильтры/даты — в описание.
Предложена новая арка (ждёт решения пользователя): кейс 1 «Чем плох OFFSET?» — дубль, призрак, глубина (индекс уже есть),
🔴🔴🔴; кейс 2 «Закладка вместо счёта» — `>`, `>=`, пара, затем выгрузка 1000/1000, 🟢🟢🟢; цена — нет прыжка на страницу N.
- Пользователь выбрал вариант «А» — арка v2 (все беды OFFSET до закладки, табло из трёх ламп, ≈ 20 кадров). Записана в
  `docs/episodes/13-keyset.md` («Арка v2», «Картинка», «MVP v2 (план)»). Перестроен MVP под арку v2 (следующая сессия).
