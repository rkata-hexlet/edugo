# Архитектура

## Зоны
| зона | каталог | что там | как часто меняется |
|---|---|---|---|
| каркас | `src/engine/` | контракт сцены, плеер (play/pause/шаг/скорость), примитивы отрисовки | редко |
| серийный набор | `src/kit/` | тема, иконки, виджеты, подсветка SQL, персонажи, motion.css, режиссёр серии `director` — общий визуальный язык и грамматика подачи эпизодов (ADR-0002, ADR-0005) | при полировке |
| прикладной код | `src/scenes/NN-name/` | эпизоды: `sim.ts` (модель), `script.ts` (акты), `view.ts` (отрисовка) | постоянно |
| composition root | `src/main.ts` | реестр сцен + сборка плеера | при добавлении сцены |

## Сущности
- `Scene<S>` (`engine/contract.ts`) — просчитанная последовательность `Step<S>` (акт, подпись,
  состояние) + `render(pen, state)`. Плеер ничего не знает о содержимом сцены, сцена — о плеере.
- `Pen` (`engine/contract.ts`, реализация `engine/pen.ts`) — узкий порт отрисовки: `rect/text/line/path/group`
  по ключам. Тот же ключ в следующем кадре — тот же SVG-узел, поэтому переезд группы (x/y и
  `Transform`: поворот, масштаб вокруг `origin`) анимируется CSS-транзишеном сам. Сцены рисуют
  только через `Pen`, DOM не трогают. Порядок наложения: слой (`layer`: back < main < front < top,
  по умолчанию main) + порядок рисования внутри слоя. Узел, которого нет в новом кадре, гаснет
  `LEAVE_MS` (класс `.leaving`); плеер передаёт `frame(…, { instant })` при перемотке и прыжках —
  тогда сразу и без движения: класс `.no-anim` на время кадра, новым узлам — `animation: none`. `text` принимает `Span[]` (куски со своими атрибутами); `measure` — размер текста
  для подгонки рамки (в тестах — оценка по числу символов).
- `kit/` — визуальный язык серии, рисует только через `Pen`: `theme` (палитра, цвета подов
  `ACTOR`, кегли `SIZE` с минимумом 18, `DIM`, `SAFE_BOTTOM` — низ кадра под подпись плеера),
  `icons` (замок, талон, часы, ключ… — пути 24×24 вместо эмодзи), `widgets` (панель с плоской
  тенью, пузырь с хвостом по `measure`, пилюля, лампа, табло главы `board`, окно SQL и его строки с
  префиксом пода `podSql`, штамп перемотки `stamp`, `iconText`, разовый эффект `once`, плашка главы),
  `director` (режиссёр серии, см. `script.ts` ниже; типы `Board`, `Lamp`, `Verdict`), `sql`
  (`highlightSql` → `Span[]`), `characters` (под-«боб» с эмоцией `Mood` и взглядом `Look`,
  слон-Postgres, лицо Почты), `widgets.meter` (полоса нагрузки с потолком), `props` (предметы мира: кружка, покупатель, кнопка, замок `lock`, бирка замка `lockTag`, корона лидера `crown`), `code` (окно кода на Go `codeWindow`, подсветка `highlightGo`; SQL внутри `…` — как SQL), `motion.css` (словарь движений `fx-*`: pop, slide, rise,
  stamp, draw, hop, shake, jolt, nod, pulse, cascade — всё в первые 450 мс кадра; `.tw` — плавная смена размера рамки между кадрами). Kit не знает ни
  плеера, ни моделей эпизодов: эмоцию, взгляд и эффект выбирает `view.ts` по состоянию кадра и
  `World.events`. Разовый эффект — новый ключ узла (`World.frame` в ключе), свежий стол — `World.scene`.
- `SceneMeta` (`Scene.meta`) — номер, название, подзаголовок, финальная фраза эпизода: заголовок
  плеера, обложка и финальная карточка.
- `Sound` (`engine/contract.ts`, реализация `engine/audio.ts` на Web Audio) — узкий порт звука:
  `tone`, `noise`, `babble(voice, text)`. Процедурный синтез, без файлов; AudioContext — по первому
  жесту пользователя. Mute — в localStorage (удобство зрителя).
- `Takes` (`engine/takes.ts`) — дубли живого диктора (ADR-0004): ключ — хэш текста кадра (`takeKey`),
  длительности — `public/voice/<сцена>/takes.json`, файлы — `<ключ>.ogg` рядом. `loadTakes` грузит
  справочник до сборки плеера; `script`/`firstLine` — порядок чтения для суфлёра.
- Суфлёр (`engine/recorder.ts`, `?record`, только dev) — кадр и текст крупно, пробел — дубль и сразу
  следующий; запись уходит `POST /__voice/<сцена>/<ключ>` в плагин `vite.config.ts`, тот зовёт
  `scripts/voice.mjs` (ffmpeg: щелчки, тишина, шум, громкость) и раздаёт `/voice/…` с диска.
- `scripts/ep.mjs` (`npm run ep -- NN`) — эпизод в своей папке без переключения веток: ветка `episode/NN-*` →
  git worktree `../<репо>-NN`, dev-сервер на порту `51NN`, суфлёр `?scene=NN&record`.
- Расход токенов (`npm run tokens`) — скрипт вне репо `~/.claude/scripts/tokens.py`: сводка каждой сессии Claude
  Code в архив `~/.claude/token-stats/`, отчёт по неделям, веткам, агентам. Архив пополняет хук `SessionEnd`
  (`.claude/settings.json`), там же строка статуса с размером контекста (`~/.claude/scripts/statusline.py`).
- `Narrator` (`engine/narrator.ts`) — закадровый голос: дубль из `Takes`, без дубля — Web Speech API. Закадр режется на куски
  `phrases` (предложения, длинные — по паузе, ≤ `MAX_PHRASE` знаков = строка субтитра); `speechParts`
  читает кусок одним русским голосом (синтез — черновик, озвучивает пользователь; решение 23.10), словарь сцены
  (`Scene.pronounce`, исключения вроде букв подов) — только для речи. `onPhrase(i)` —
  начало куска: плеер меняет субтитр в такт голосу; у дубля и в записи субтитр идёт по
  `phraseStarts` (расчётный темп, растянутый на длину дубля). Страховочный таймер — если синтез не сообщит о конце; без голоса
  или в mute — выжидает расчётное время. `VOICE_DELAY_MS` — пауза перед голосом.
- Контракт кадра: `Step.narration` (текст диктора);
  `Pen.path`, `Pen.group(…, attrs)` — для дуг и приглушения (фокус).
- Плеер (`engine/player.ts`) — контроллер: кадры, звук, диктор, автопроигрывание, ←/→/пробел,
  M (звук), C (субтитры), F (полный экран), D (dev); номер кадра в `#step=N` (ссылка на кадр для
  обсуждения). Автопроигрывание листает, когда истёк `hold` и диктор договорил; бормотание
  персонажей под диктором тише; после голоса — пауза `POST_VOICE_MS`. Звучит только шаг вперёд и
  старт воспроизведения; перемотка обрывает звук. Шрифты (`@fontsource`: Inter, JetBrains Mono)
  ждёт до первого кадра, не дольше `FONTS_MS`.
- Шкала записи (`engine/timeline.ts`): `frameMs` (время кадра), `frameSeconds` (дольше из кадра и
  голоса: длина дубля или расчётный темп), `timeline` (заставка → кадры → финал не короче своей фразы),
  `frameAt`. Общая для плеера и рендера.
- Рендер в mp4 (`?capture&render`, `exposeRender` в `player.ts` → `window.__edugo`; `scripts/render.mjs`):
  перемотка на момент t с остановкой анимаций, звук через `WebAudioSound.offline(OfflineAudioContext)`
  + дубли диктора в той же дорожке, WAV кусками, склейка ffmpeg (ADR-0003, ADR-0004, docs/recording.md).
- Снимки кадров (`scripts/shots.mjs`, `npm run shots`): `?capture#step=N` в headless Chrome с dev-сервера, анимации
  доведены до конца, PNG 1280×720 в `out/shots/NN/`, `--sheet` — контактные листы 2×3 (`montage`).
- Оболочка (`engine/shell.ts`, стили `engine/player.css`) — только DOM: кадр 16:9 по окну,
  подпись кадра оверлеем внутри кадра (попадает в запись), субтитры диктора по CC (только в плеере), панель (play, прогресс
  сегментами по актам, скорость, CC, звук, полный экран), которая прячется при проигрывании без
  движения мыши; обложка (`Scene.meta`; только при ссылке без `#step` и без `?dev`) и финальная
  карточка (после последнего кадра); dev-полоса (`?dev` / D) — список актов и номер кадра.
  Действия зрителя отдаёт плееру через `ShellEvents`, состояние не держит.
- `sim.ts` — чистая модель предметной области (поды, строки таблицы, транзакции, блокировки,
  журнал внешних эффектов — `letters`). Детерминирована, покрывается тестами. Предикаты
  `duplicates` / `stuck` — по ним тест сверяет табло попыток (`World.board`) с моделью.
- `script.ts` — сценарий: подкласс общего `kit/director` `Director<Focus, World>` (мир эпизода
  реализует `Staged`: sql, db, plate, stamp, term, focus, chapter, board, events, frame, scene).
  `shot(подпись, действия, {verdict})` применяет операции модели и снимает кадр (`structuredClone`).
  Реплики/SQL/титры живут один кадр; глава (номер кейса) и табло попыток живут в `Director` и
  переживают «свежий стол» (`scene` с новым миром). Своё у эпизода — в хуках: `hold` (время кадра
  без голоса), `clear` (что ещё живёт один кадр: реплики подов, Почта, `Actor.acts`), `finish`
  (события и флаги подачи после табло: «?» над подом, `replay` итога), `carded` (титр звучит).
- Поля состояния для подачи (пишет сценарий, рисует `view.ts`): `doubt` — «?» у пода (нить «жив ли?»),
  `clash` — плашка «🎫≠🎫» до конца сцены, `keyed` — письма с ключом, `Actor.thought` — мысль пода
  (устаревшая проверка), `Board.focus` — подсвеченная попытка; `frame`, `scene` — номера для эффектов.
- `World.events` — журнал событий кадра (замок, коммит, 0 строк, письмо, дубль, пропуск…). Пишут
  операции модели (`sim.ts`) и глаголы сценария; `Director.shot` очищает его в начале кадра.
- `sound.ts` — озвучка кадра по журналу событий (карта sound-designer v5) + голоса реплик. Звуки
  событий — в окне `EVENT_WINDOW` (0.45 с) в такт эффектам кадра, бормотание — с `BABBLE_AT` (0.5 с,
  вместе с диктором, тихо). События подачи (`rewind`, `verdict`, `doubt`, `clash`, `ghost`) пишет
  `Director.shot` и глаголы сценария; повтор (`scene(…, { replay: true })`) — без «перелистывания».
- `view.ts` — рисует состояние через `Pen` и kit. Сетка: шапка; слева таблица и окно SQL (только
  в кадрах с SQL); в центре поды; справа Почта и табло; ниже `SAFE_BOTTOM` пусто. Поды неподвижны;
  стрелки (смотрит / держит / ждёт / пропустил / отправил) строятся только из состояния кадра.
- `view.test.ts` — все кадры через фейковый `Pen`: кегль ≥ 18, низ кадра свободен, нет эмодзи и NaN.
- `sim.test.ts` — модель (семантика Postgres) + «сценарий не врёт» (итог каждого акта);
  `sound.test.ts` — журнал событий ключевых кадров + озвучка всех кадров через фейк `Sound`.

## Эпизод 02 (`scenes/02-cache/`, `?scene=02`)
Та же раскладка файлов, что у 01. `sim.ts` — таблица `links` (MVCC: чужая незакоммиченная правка не видна,
чтение не ждёт), Redis с TTL (`Entry.expiresAt`; кластер — `nodes` и узел слота горячего ключа `hotNode`),
карман L1 пода (`Actor.l1`), журнал ответов браузерам (`clicks`, `stale` = расходится с закоммиченным), нагрузка
формулой от потока (`dbLoad`, `nodeLoads`). `Actor.acts` — что под сделал в кадре: из них `view.ts` строит
стрелки (к Redis, к строке базы мимо Redis, ответ браузеру, рассылка). `World.replay` — кадр итога: звук тише и
без тревоги (`sound(s, w, replay)`).

## Порядок сборки (main.ts)
1. Импорт сцен → реестр (`Record<string, Scene<any>>`: у каждой сцены свой тип состояния). 2. Выбор сцены (`?scene=01`). 3. `loadTakes(scene.id)` — справочник дублей.
4. `mountPlayer(host, scene, takes)` или `mountRecorder(…)` при `?record` — сами создают SVG и `SvgPen`.

## Граф зависимостей
```
scripts/render.mjs ──(puppeteer, ?capture&render)──► страница плеера
scripts/shots.mjs ──(puppeteer, ?capture#step=N; montage)──► dev-сервер, снимки кадров
vite.config.ts (dev) ──► scripts/voice.mjs ──► ffmpeg
scripts/ep.mjs ──(git worktree)──► vite в папке эпизода
main.ts ──► engine/takes ──► engine/contract (тип Step)
   ├──► engine/recorder ──► engine/pen, engine/takes
   └──► engine/player ──► engine/pen ──► engine/contract
                    ├──────► engine/timeline ──► engine/narrator ──► engine/takes
                    └──────► engine/shell ──► engine/contract
   └──────► scenes/NN/index ──► script ──► sim
                         ├────► view ──► sim, script(clock), kit
                         └────► sound ──► sim, engine/audio(syllables)
scenes/* ──► engine/contract (только типы)
scenes/* ──► kit ──► engine/contract   (с этапа 3; kit не знает сцен и плеера)
   sim ──► kit/director (только типы Board, Verdict); script ──► kit/director (Director)
```
Сцены не импортируют друг друга. Циклов нет.
