# Конструктор, уровень 1 — tech-expert, этап 5, сверка текстов после дизайнеров

Прошлый разбор — `c01-tech-expert-stage5.md`. Проверено по `src/constructor/model/sim.ts`,
`levels/01-booking.ts` (failures, `alt.T`), `ui/game.ts` (цель, PHASE, победа), `ui/view.ts` (подписи).
Модель не менялась; ниже только то, где текст расходится с моделью или с жизнью. Трасса — ручная, по коду.

## Ошибка

### 1. Победа «поставщик молчал — гость узнавал сразу» — неправда для T O B K
Отказ (`refused`) в модели даёт только breaker. В D1 он не размыкается (≈50% неудач при пороге 16/20, и с R тоже:
на волну 14 исходов, 7 неудач). В D2 для T O B K по коду:
- размыкание на t=91 (16-я неудача из 20), open 10 с; дальше цикл half → пробный вызов в зависшего → таймаут 3 с →
  снова open: пробы на 200, 340, 480, **620**;
- проба 620 стартует, пока поставщик молчит, на 640 её соединение «рвётся», но неудача засчитывается по таймауту
  на 650 → open до **750**;
- поставщик работает с 640, а отказ получают: волна 640 (8 гостей — half, проба в полёте), волны 660–740 (40),
  волна 760 кроме пробы (7). Итого ≈55 отказов при работающем поставщике.
Для T O R K J B тайминги другие (повторы, jitter) — проверить тестом; механизм тот же, совпадение пробы с подъёмом
зависит от фазы цикла.
В жизни это верно и важно: breaker отказывает, пока не истёк его open-таймаут, даже если зависимость уже ожила, —
это его цена. Сломан только текст.
Замена: «Отказы честные: брони нет, и гость узнавал это сразу, а не через 10 с.» Если хочется показать цену:
добавить «Breaker отказывал и несколько секунд после того, как поставщик ожил, — это его цена.»
(Попутно в модели: «соединение рвётся» на 640 должно давать ошибку сразу, а не по таймауту на 650; на исход это не
влияет — open до 740 вместо 750.)

### 2. П1 `alt.T` «все 3 с ожидания» — неверно при включённом ретрае
`alt` выбирается по первому включённому кирпичу из `BRICKS`, T — первый, значит текст показан и для T R, T R J,
T R K… без O. Там бронь держит соединение всё время всех попыток и пауз (`holdsSlot` снимается только в `answer`),
до 9,5 с, а не 3 с. Без R — верно: 4 медленных × 3 с + 4 быстрых × 0,5 с + поиск ≈ 14,8 слот-с на 2 с при ёмкости
12 — «приходят чаще, чем уходят» правда. Для жизни верно: `BeginTx` → HTTP-вызов → `Commit` держит соединение
пула всё время вызова; таймаут сокращает ожидание, но не отпускает соединение раньше.
Замена: «Таймаут работает, но вызов идёт внутри транзакции: пока ждём поставщика, соединение пула занято. Брони
приходят чаще, чем уходят, — поиску не достаётся.»

## Неточность

### 3. П8 «А часть этих гостей могла получить бронь сразу» — не «сразу» и не без условий
У T O в D1 медленные первые попытки детерминированы (половина волны); повтор попадает на быстрый сервер с
вероятностью 1/2 (`unit < 0.5`). То есть бронь гость получил бы **повтором, после 3 с таймаута**, а не сразу. Кроме
того, без K такой повтор дал бы вторую бронь (первая всё равно доделается на 30 с) — П3.
Замена: «А часть этих гостей получила бы бронь повтором: другой сервер поставщика отвечает быстро.»
(Фраза подсказывает R, хотя экономное решение T O B K без него, — решать вам/level-designer; технически после
замены верно.)

### 4. Цель: «Поставщик то отвечает по 30 с, то молчит» — противоречит PHASE.D1
Беда A — не «отвечает по 30 с», а «часть ответов идёт 30 с» (один завис, повтор помогает). Фраза цели возвращает
модель «весь поставщик тормозит», против которой был п.1 прошлого разбора.
Замена: «У поставщика то часть ответов идёт 30 с, то он молчит минуту.»
Остальное в цели верно: «проверяем» с номером брони — допустимо (номер = наш ключ K у поставщика, по нему сверка);
пул 6 общий с поиском.

### 5. П4.why «медленному поставщику пришла пачка сверху»
Та же рамка «медленный поставщик» (перегруз), а в A — один зависший сервер. Механизм (таймауты одной волны в один
тик → повторы в один тик) верен. «Повторы за 0,3 с: N» = `retryArrivals` за окно (t−3, t] тиков = 0,3 с — верно;
счёт ведётся только пока поставщик не молчит, и подпись показывается только при N > 0 — не врёт.
Замена: «Запросы одной волны отвалились по таймауту в один момент и повторились тоже разом: к поставщику пришла
пачка повторов сверх обычного потока.»

## Верно, правок не нужно
- PHASE.D1 «часть ответов идёт 30 с», D2 «поставщик молчит минуту» (down 40–640 тиков = 60 с), статусы поставщика
  «часть ответов 30 с» / «молчит» — согласуются с прошлым разбором (A — хвостовая задержка, B — завис, не «лёг»).
- «брони ждут соединения: N» = бронь в очереди пула (`bookingsWaiting`) — верно.
- П8 «без нашего ключа её у него не найти», «брони без нашего ключа» — верно (решение T O B K).
- П2, П3, П5, П6, П7 — сходятся с моделью.
