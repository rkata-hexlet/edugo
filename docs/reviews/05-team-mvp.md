## tech-expert — две ошибки голоса, остальное верно
1. **Кадр 21 / пометка SERIALIZABLE** «конфликты разных строк» — неверная модель: запись в разные строки без чтения
   чужих данных не конфликт. SSI ловит, когда каждая решала по данным, которые меняет другая; гарантия — «как будто по
   очереди». Голос: «ловит даже случаи, когда транзакции пишут в разные строки, но каждая решала по данным, которые
   меняет другая». Пометка: «как будто по очереди».
2. **Кадр 3** «замок появляется, только когда пишут» противоречит FOR UPDATE в кадре 17. «Обычный SELECT строку не
   запирает; замок появляется, когда в неё пишут, и держится до конца транзакции». ACCESS SHARE голосом не оговаривать.
Искажения: кадр 6 «честный ноль» → «ноль, будто всё в порядке»; финал «в самой записи» → «в самом UPDATE»; кадр 17
«плюс свои изменения» (не блокер); хук «1 → 0» в одной ячейке спорит с «не правит на месте» — показывать 0 под замком.
В сценарий: MariaDB 11.6+ `innodb_snapshot_isolation=ON` даёт ошибку на RR; 40001 только если A закоммитил.
Правки tech-expert внесены 23.10 (кадры 3, 6, 17, 21, пометка SERIALIZABLE, финал, хук без «1 → 0»).
