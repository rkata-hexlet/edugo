# Эпизод 07 — tech-expert после MVP и стиля (24.10)

Ошибки (исправлены): кадр 27 — 40P01 и 40001 различаются причиной и лечением, а не тем, сохранится ли ответ после
повтора (после 40P01 остаток тоже мог измениться); кадр 30 — «ждущий ничего не держит» верно лишь для двух товаров,
общее правило — «все идут в одну сторону, встречных нет»; кадр 23 — B ждёт до коммита A, а не весь его заказ.
Вкус (взято): «списание чайника отменяется» (11), «без кольца» (17), «Каждый ждал секунду.» (17), «пара строк» (20),
«потом одним UPDATE» (25). Код Go (pgx v5), SQL-панель и модель верны.

В описание ролика: жертву выбирает процесс, у которого первым истёк deadlock_timeout (InnoDB, SQL Server — по
стоимости); `log_lock_waits`, `pg_locks`, `pg_blocking_pids()`; `lock_timeout`/`statement_timeout` меняют одну ошибку на
другую; сортировка без повтора — только на READ COMMITTED; `slices.SortFunc` сортирует корзину вызывающего на месте —
лучше копию; `FOR NO KEY UPDATE` вместо `FOR UPDATE` при внешних ключах на products; повтор — лимит, backoff с jitter,
`ctx.Err()`, внешние эффекты вне транзакции; порядок и между таблицами, неявные замки (FK, триггеры); deadlock троих и на
одной строке (FOR SHARE → UPDATE); распределённый deadlock детектор не видит; `pg_advisory_xact_lock`.
