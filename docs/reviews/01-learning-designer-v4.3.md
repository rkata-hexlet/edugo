# Эпизод 01 v4.3 — разбор learning-designer (18.10)

Номера кадров — по «Закадр v4.3» в `docs/episodes/01-skip-locked.md` (= `#step=N`).
Сюжет утверждён; разбор — о подаче. Статус правок — в плане полировки (`docs/state.md`).

## Главные риски непонимания
1. **26–31: нить «жив ли B?» вводится только на 31**, а картинка её опровергает (пунктирный под
   «B · упал» — зритель знает ответ, герои нет). Вариант 2 не показывает «навсегда» — время стоит.
2. **29, 32, 33, 40: картинка опережает голос на 8–20 с.** 29 — уже вариант 2, голос про вариант 1;
   32 — 4 предложения над статичным табло; 33 — колонки, токен, срок, полоса, SQL, штамп, часы
   разом; 40 — перемотка и её итог в одном кадре.
3. **34–38: «B действует по устаревшей проверке» не нарисовано.** Пузырь «успею» живёт кадр; ✓ 13 px,
   полоса 5 px, курсор 3 px; после перехвата `carrying=1` у B и C → строка нейтральная как раз когда
   «задача стала C»; обе стрелки сплошные; красная часть полосы с самого начала — «срок вышел» не событие.
4. **Мир недоопределён до первой поломки:** нет «нормального» прогона, нет легенды стрелок, не объяснено
   табло; слова без опоры — COMMIT (12), транзакция, «соединение занято» (29), токен (33), «воркер».
5. **Сравнение попыток держится на голосе и мелком табло** (12 px, внизу справа); новая лампа не
   выделена; в главе 2 у вариантов 1 и 2 одинаковые лампы; штамп «⟲» живёт один кадр.

## Правки по кадрам
- **4b (новый): «норма»** — A берёт #1, письмо, done. Учит легенде стрелок и образцу «хорошо». ~6–8 с.

- 5: голос называет два критерия табло, табло подсвечено.
- 7: «и по дублям это красное», лампа пульсирует. 8: мьютекс — замок внутри пода (контраст с замком на
  строке в 17). 8–9: бормотание и пузырь БД дублируют голос — оставить одно.
- 11: фокус A, B, C + SQL (не только A). 12: объяснить COMMIT при первом упоминании.
- 14: оставить «compare-and-set: проверка и запись одним действием»; «оптимистичный/пессимистичный» —
  парой на 17 (проверить tech-expert). 15: «на следующих двух задачах». 16: слова критериев как на табло.
- 17: мотив «чтобы никто не проигрывал зря». 20: «C всё ещё стоит у первой строки, а держит её теперь B»;

  `SKIP LOCKED` цветом «без ожидания».

- 27: линия B→БД «соединение занято», исчезает на 29. 28: реплику БД озвучить, не читать.
- 29 → 29a (вердикт варианта 1) + 29b (вариант 2); постоянная шапка «вариант N».
- 31: две копии B — «завис 💤» и «упал ✕» — снаружи одинаковы; часы вперёд на час-два (починить
  `clock()`: при t ≥ 3600 будет «12:60»).

- 33 → 33a (колонки пустые, «договоримся о сроке») + 33b (токен = номер захвата, срок по часам БД);
  часы подписать «часы БД», поставить у слона.

- 37: карточка окна в стиле кадра 6. 38: голос в две фразы, `🎫≠🎫` держать до конца.
- 39: рифма с кадром 7 — скобка «одна строка, два письма».
- 40 → 40a (перемотка к `beforeZombie`, 🔑 появляется) + 40b (письма, «↺ повтор»; голос «какое бы ни

## Доработка плеера/отрисовки
- **Важно:** подсобытия внутри кадра (`cues` по доле текста / `boundary` Web Speech) или нарезка кадров;
  фокус по предложениям; постоянная шапка варианта; цвет строки по токену; подсветка строк SQL;
  размеры 12–13 px → 16–18 px (полоса срока, ✓, курсор, табло).
- **Желательно:** пульс новой лампы, анимация курсора срока, бейдж «часы БД», `clock()` ≥ 3600,
  реплики БД не поверх голоса; DIM 0.25 → 0.4–0.5; анимированная смена стола (три сброса в главе 2
  выглядят как баг).

## Три правки с наибольшим выигрышем
1. Разрезать 29, 33, 40 и привязать появление элементов к голосу.
2. Вопрос «жив ли B?» — на плашку главы 2, «?» над B до 41, на 31 «завис / упал выглядят одинаково».
3. Нарисовать устаревшую проверку B (мысль ✓, окно, цвет по токену, бледная стрелка); итог 42–44
   пересыграть на тех же образах.
4. (если останется время) кадр-«норма» 4b.
