# Эпизод 02 — смысл после стиля (tech-expert, фаза 2, этап 2, 27.10)

Модель `sim.ts` сверена с панелью и закадром: порядок DEL / BEGIN / UPDATE / COMMIT / PUBLISH, чтение только
закоммиченного, просроченную запись Redis не отдаёт. Обложка и outro выполнимы (каждый SET с EX).

## Исправлено (обязательно)
- **18** — «лишь миллисекунды» обещало, что других путей к старой копии нет; остаётся stale set (прочитал до COMMIT,
  SET после DEL). Теперь «каждый промах после удаления прочитает promo».
- **21** — «но теперь у копии есть срок» звучало как новый механизм; срок был всегда: «как у любой в нашем кэше».
- **22** — «Redis сам удаляет запись» → «перестаёт отдавать запись и сам её убирает» (ленивое удаление); + «если
  удаление ключа почему-то не сработало» — честно закрывает и падение пода, и stale set без нового механизма в кадре.
- **33** — «Спас порядок» → «Выручил порядок… окно вранья сжалось до миллисекунд»: дыру закрывает TTL (кадр 34).

## Исправлено (желательно)
- **17** — «правки пока нет» → «правка не закоммичена и для остальных её пока нет».
- **29** — «через пару секунд» → «через несколько секунд»: часы прыгают на 4 с (модель не трогал).

## Не в ролик, в описание
stale set — отдельной фразой не вносим (нет носителя на картинке, сюжет утверждён); stampede; отставание реплики
Postgres; CLIENT TRACKING; решардинг слотов — дописано в `docs/episodes/02-cache.md`.
