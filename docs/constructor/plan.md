# План MVP конструктора (ADR-0007)

Один уровень, мир отеля, локально (`npm run dev`). Цель MVP — понять, интересно ли проходить уровень.
**До утверждения пользователем ничего не вылизываем** (решение 01.11): серые фигуры, без звука, без анимационной
полировки, разборы агентов — по минимуму. Шлифовка и полная техническая сверка — после утверждения.

## Готово, когда
- уровень открывается в `npm run dev` (`/play.html`), в портретной колонке (ширина телефона);
- наивная схема проваливается на каждой беде; стоп-кадр показывает, что и где сломалось, и почему (отсылку к кейсу ролика 10 пользователь снял 01.11);
- есть ≥ 2 рабочих решения с разным счётом табло (задержка, лишние запросы, число кирпичей);
- модель детерминирована, табличный тест «кирпичи × беды → исход» зелёный;
- пользователь прошёл уровень сам.

## Решения по развилкам (Claude, по поручению пользователя 01.11)
- **Портрет** — цель Mini App на телефоне; на десктопе колонка по центру.
- **Уровень-сочетание по эпизоду 10** «Бронь через медленного поставщика»: кирпичи — таймаут, вызов вне транзакции,
  ретрай, ключ идемпотентности, backoff + jitter, circuit breaker; беды — поставщик тормозит, поставщик лёг на минуту;
  ловушка — ретрай без ключа → две брони. Состав уточняет level-designer. Уровни по одному кирпичу — потом: они не
  ответят, интересно ли.
- **Без звука** в MVP.
- **Ветка `constructor/mvp` от `master`**, вливается по этапам при зелёных тестах: эпизоды не затрагивает.
- **Раскладка:** прикладная зона `src/constructor/` (`model/`, `levels/`, `ui/`), своя точка входа `play.html` →
  `src/constructor/main.ts` (composition root конструктора). Код сцен не импортирует; общее — `engine/` (`Pen`) и `kit/`.
  Плеер эпизодов не трогаем: у него линейные кадры, здесь — свой маленький контроллер прогона.

## Этапы (каждый — своя сессия, состояние — `docs/constructor/state.md`)
1. **Уровень на бумаге** — level-designer, короткий проход: цель, палитра, гнёзда, беды, ловушка, табло →
   `docs/constructor/level-01.md`. Таблицу «кирпичи × беды → исход» набрасываю сам по эпизоду 10 и разбору
   `docs/reviews/10-tech-expert-arc.md`; tech-expert — после утверждения.
2. **Модель** `src/constructor/model/`: мир в тиках, кирпич — правило поведения; табличный тест.
3. **Серый интерфейс**: схема с гнёздами, кирпич касанием, «Запуск» → прогон через `Pen`/`kit`, стоп-кадр провала,
   табло победы.
4. **Показ пользователю** (снимки headless в портрете + живой прогон). ★ Стоп: утверждение механики.
5. После утверждения: tech-expert (таблица и модель), level-designer и learning-designer по снимкам, правки, показ 3–5
   посторонним.

## Команда
level-designer (sonnet) — этап 1 и после утверждения; tech-expert (opus) — после утверждения; learning-designer
(sonnet) — после утверждения; motion-designer — не раньше решения о продолжении.
