# edugo

Короткие анимированные сцены с лёгким юмором, объясняющие темы Go и бэкенда (гонки, блокировки,
транзакции). Сцена = детерминированная симуляция + отрисовка в браузере (SVG).
Карта кода — `docs/architecture.md`, текущее состояние — `docs/state.md`, сценарии — `docs/episodes/`.

Команды: `npm run dev` (просмотр), `npm test` (vitest), `npm run check` (tsc), `npm run build`,
`npm run render` (mp4), `npm run narration` (закадр для правки).
Удалённый репозиторий: `origin` = `git@github.com:rkata-hexlet/edugo.git`, ветка `master`.

## Для кого и как выпускаем
**Продукт — mp4-ролик для школы программирования, раз в неделю**; школа публикует его в своих
соцсетях, пользователь — в своём Telegram-канале (личный бренд). **Качество материала важнее
скорости и количества**: ролик уходит наружу под именем автора, переделать после публикации нельзя.
Готово = готовый mp4 (картинка, звук, голос; без субтитров — решение пользователя 21.10), проверенный просмотром целиком. Веб-плеер —
инструмент сборки и проверки, а не продукт. Подкреплено: решение пользователя 19.10.
**mp4 рендерю только по команде пользователя**, когда эпизод утверждён к выпуску; пока идут правки —
проверка только в браузере (`npm run dev`). Подкреплено: 19.10 — «зачем mp4, мы ещё править будем».

## Критерий качества эпизода
**Посторонний зритель понимает базу с первого просмотра, не напрягаясь**; термины и тонкости
ложатся поверх понятой базы. Пользователь смотрит эпизод не разбирая, а проверяя, «заходит» ли.
Проверяет `learning-designer`.

## Процесс эпизода
- **Ветки: эпизод — своя, общий код — своя.** `episode/NN-тема` — сценарий, сцена, дубли; в `master` после
  выпуска. Общий код (`engine/`, `kit/`, скрипты) — `refactor/…` или `engine/…` от `master`, вливается сразу,
  как только тесты зелёные и выпущенные эпизоды не изменились (эталон кадров или снимки); ветка эпизода потом
  подтягивает `master`. Иначе общий код застревает в ветке неготового эпизода. Решение пользователя 22.10;
  история до него (эпизод 02 в `master`) не переписывается.
- **Темы и кейсы предлагаю от самых востребованных к редким**: насколько часто обычный бэкендер встречает это в
  работе. Редкое — в конец списка или в «отдельный эпизод». Решение пользователя 23.10.
- **Каждый эпизод начинается с MVP**: все акты подряд, серые фигуры + подписи, без полировки.
  Показать пользователю → обсудить сюжет → только потом детали и анимация. Полировать до
  утверждения сюжета — пустая трата: акты переписываются.
- Сценарий живёт в `docs/episodes/NN-*.md` и обновляется после каждого обсуждения.
- **Закадр правит пользователь одним куском**: я выгружаю весь текст эпизода из `script.ts` в
  `docs/episodes/NN-narration.md` (`npm run narration`, строка = кадр с номером), пользователь
  правит, я разношу обратно в `script.ts` и сценарий и выгружаю файл заново (номера сдвигаются);
  смысл правок сверяет tech-expert, реплики — глазами на кадре. Решение пользователя 19.10.
- **Голос — дубли пользователя** (ADR-0004): пишет суфлёром `?record`, дубль привязан к тексту кадра.
  Правка закадра после записи — сказать пользователю, какие кадры перечитать (суфлёр начнёт с них).
  Синтез — только запасной для кадров без дубля и для MVP до записи. Решение пользователя 21.10; подкреплено
  после записи эпизода 01 — «понравилось, как записывали, так и будем делать».
- **Тексты идут цепочкой** scriptwriter (черновик) → tech-writer (стиль) → tech-expert (смысл) →
  learning-designer (восприятие). Смысл проверять после стиля: правка стиля после смысла ломала
  его (кадры 9, 14, 20 эпизода 01). Текст, переписанный пользователем или внешней моделью, — так
  же: стиль принимаем, смысл сверяет tech-expert, реплики — глазами на кадре. Подкреплено: живой
  закадр v5.1 принёс 8 смысловых огрехов (чужая строка под замком, «тут же», «ровно одно письмо»)
  и две реплики, наехавшие на шапку.
- Перед полировкой — план этапов по образцу `docs/plan-01-polish.md`; рецензентам показывать
  контактные листы кадров (`?capture` + headless Chrome), а не только код: по картинке они ловят
  реальные дефекты.

## Подача серии (эталон — эпизод 01 v5)
Пользователь утвердил стиль повествования и подход эпизода 01 как стандарт серии («отлично
получилось, придерживаемся в других сериях»). Новый эпизод строится так же; отступление — только
через обсуждение.
- **Начало — знакомство с системой, потом хук:** зритель сначала видит, что за сервис и кто в нём кто,
  и только потом — поломку. Мир прошлого эпизода вводится его же сценой. Решение пользователя 22.10 (эпизод 03:
  «что значит выложили ссылку в канал? Нужно представить систему»; правило серии — при старте 04).
- **Мир — на 2–3 эпизода, потом новый**: один сервис-контекст не тянем через всю серию, так богаче. Мир выбираем,
  где кейсы темы возникают естественно; отсылка назад работает и между мирами (сцена прошлого эпизода в кадре).
  Решение пользователя 23.10 (сокращатель ссылок — эпизоды 02–04, дальше другой).
- **Арка:** хук — проблема в чистом виде (гонка: три пода, три письма) → кадр «нормы», как должно
  быть → кейсы. Кейс открывается полноэкранной плашкой «Кейс N из M» с вопросом; попытки идут от
  наивной к верной, каждая пробуется на одинаковом старте. Следующий кейс ломает «починили».
- **Близость к решению видна без подписей:** табло попыток с двумя критериями главы; лампа
  загорается, когда результат уже виден на картинке; критерии названы голосом. Табло сверяет тест.
- **Рифма кадров:** поломка позднего кейса повторяет образ хука (там три письма — тут два при
  одной строке `done`), чтобы зритель узнал проблему.
- **Сквозная нить-вопрос** держит паузу и ожидание (кейс 2: «жив ли B?» — от «?» над подом до
  его пробуждения); мысль персонажа висит, пока она — его заблуждение («Время ещё есть — успею!»).
- **Альтернативы — перемоткой:** штамп «⟲ Иначе: …» / «⟲ Вернёмся: …» и та же сцена с другой
  развилки, а не новый мир.
- **Итог — повтор уже виденных образов** (сцены из актов, `Director.scene(…, {replay})`), а не
  конспект текстом. Главный вывод — одной фразой на финальной карточке (`Scene.meta.outro`), её же читает диктор.
- **Картинка раньше термина; у каждой абстракции — видимый носитель** (время — часы БД, срок —
  `lease_until` в строке, «проверил и уснул» — мысль над подом). Голос без носителя «не заходит».
- **«Непонятно» чинить фразой с явной причиной** (порядок событий, почему это не улучшение), а не
  новым элементом экрана.
- **Мир неподвижен, говорят стрелки, цвет и эмоции персонажей** (поды-«бобы», БД-персонаж,
  внешний приёмник вне таблицы — эффект, который таблица не видит). Юмор — в персонажах и
  реакциях, не в шутках голосом.
- **Движение и звук — только по событиям модели**, в первые 0,45 с кадра; голос диктора — с 0,5 с.
  При перемотке движения нет. **Длительность кадра и ролика не ограничиваем**: кадр держится, пока
  звучит голос; синхронность держит нарезка (одна мысль — один кадр), а не краткость фраз. Рассказ
  важнее тайминга. Подкреплено: пользователь 19.10 — погоня за таймингом рвала связность закадра.
- **Нить между эпизодами — отсылкой назад:** новый эпизод вспоминает прошлый и коротко объясняет, что
  там было на самом деле (эпизод про уровни изоляции: «в ролике про очередь задач всё шло на READ
  COMMITTED — вот почему B перепроверил статус»). Отсылка самодостаточна: сцена прошлого эпизода
  повторяется в кадре, а не «смотрите прошлый ролик». Вперёд из ролика не обещаем (переделать после
  публикации нельзя) — анонс только в описании. Решение пользователя 19.10.
- Обложка = вопрос-обещание зрителю (`Scene.meta.title/tagline`); обещание проверяет tech-expert
  (эпизод 01: «не отправить письмо дважды» было бы невыполнимым).

## На ревью проверять
- `scenes/*/sim.ts` детерминирован: без `Math.random`, `Date.now`, таймеров и DOM. Время — счётчик тиков.
- SQL/Go в подписях, SQL-панели и закадре соответствует тому, что реально делает симуляция (сцена не врёт).
- Сценарий `docs/episodes/NN-*.md` и `script.ts` сцены описывают одни и те же акты.
- `engine/contract.ts` — leaf, ничего не импортирует.
- Звук берётся **только из `World.events`**, не из сравнения кадров. Новое действие модели или
  глагол сценария, которое зритель должен услышать, пишет событие; стоп-кадры и «тихие» моменты
  выставляют флаги напрямую, без события (см. стоп-кадр гонки, хук).

- Реплика Postgres в шапке — до ~37 знаков, иначе пузырь наезжает на значок кейса (кадры 30, 34

## Текст в кадре
- **Во время ролика текста минимум**: картинка, стрелки и короткая реплика несут сюжет; подпись ≤ 2
  строк и только если без неё непонятно; не дублировать реплику/титр/ярлык. SQL в панели — только
  там, где его надо прочитать. Ролик знакомит с идеей — шпаргалки и конспекта в нём
  нет (решение пользователя); подробности и оговорки — в сценарии эпизода, материал для описания. Подкреплено: MVP эпизода 01 — пользователь и
  scriptwriter: «с текстом перебор», честный хронометраж ~3:40 при цели 3:20.
- **Постоянных индикаторов нет: элемент на экране живёт только в кадрах, где голос говорит о том
  же** (счётчик «осталось N» — только «разобрали всё» и «застряла одна»; уровень изоляции голос не
  называет — значит, и таблички нет). Висящий во всех кадрах ярлык зритель не понимает, а он теснит
  кадр. Подкреплено: 19.10 — счётчик осмыслен в 6 кадрах из 48, табличка READ COMMITTED ни в одном,
  вместе они переполнили левый верхний угол (пользователь).

## Закадровый голос
- **Связный рассказ от «мы»**: каждый кадр продолжает предыдущий (переход-связка: «раз мьютекс не
  помог…», «но и тут подвох…»), а не начинается с нуля. Полные предложения, без рубленых обрывков.
- **Без телеграфного стиля**: не «X — норма, Y — брак», не тире вместо глагола, не цепочки
  обрывков. Фразы связаны наречиями, местоимениями, союзами («поэтому», «а значит», «при этом»,
  «тот же», «этот»), с глаголом. Тире допустимо одно на кадр — как пауза перед развязкой («взялись
  за одну задачу — и ушло три письма»), держит тест. Подкреплено: третье прослушивание эпизода 01
  («режет слух, звучит резко»).
- **Живая интонация, а не сухой пересказ** (эталон — закадр эпизода 01 v5.1): рассказчик
  переживает за героев. Развязка и поворот — с восклицанием («Но тут под B отвисает!», «токен в
  строке уже чужой!»); разговорные глаголы и оценки («остаётся ни с чем», «висят в ожидании»,
  «письмо уже улетело», «затор на ровном месте», «классический race condition»); кто действует —
  назван явно («под A», «поды B и C»), а не голой буквой; короткая драматичная фраза рядом с
  длинной («Но прямо в процессе обработки под B падает.»). Термин — русским смыслом, затем
  английским именем («неблокирующий захват, non-blocking claim»). Живость важнее краткости: кадр
  держится, пока звучит голос. Подкреплено: пользователь переписал закадр v5 живее — «гораздо
  лучше стало»; 22.10 закадр эпизода 03 — «старайся всегда придерживаться: живее, конкретнее, фразы
  лучше связаны». **Конкретика мира, а не абстракция:** Kubernetes шлёт SIGTERM, OOM Killer, Telegram-канал,
  горутина, «уносит в могилу», «встали в затылок»; каждый кадр открывается связкой с прошлым («Ладно,
  попробуем…», «Зайдём с другой стороны», «Но давайте усложним жизнь…»). Эталон — закадр эпизода 03 v2.
- **Без внутреннего жаргона механизма**: голос называет событие, которое зритель видит, и его
  причину — кто пришёл, что сверила база («стоит поду C прийти за очередной задачей, как база сверит
  срок со своими часами»), а не наш рабочий ярлык («просрочку замечает следующий захват»). Слово
  голоса не совпадает со значением на экране в другом смысле («за новой задачей» при статусе
  `new` в соседней строке). Подкреплено: 19.10, кадр 39 эпизода 01 (пользователь, tech-expert).
- **Говорим о сути, а не об элементах экрана**: не «лампа», «пунктир», «табло» — а «дублей нет, но
  ждём», «B и C ждут коммита A». Картинка сама покажет, где это.
- **Терминология — как в профессии**: английский, где так говорят (race condition, SKIP LOCKED,
  lease), русский — где есть устоявшийся; значения полей по-русски («статус новый»). Английское пишем
  как есть (транслит «скип локт» — нет); латинские буквы подов — по-русски («под а», «бэ», «цэ») через
  словарь сцены `Scene.pronounce`. Синтез читает всё одним русским голосом — он черновик, озвучивает
  пользователь (решение 23.10). Решение пользователя 19.10.
- **Механизм — инженерными понятиями, без бытовых подмен**: не «номерок, блокнот, ящик, рекорд, слепок», а
  visitor ID, set в памяти, регистр, максимум ведущих нулей, sketch. Аналогия — можно, если она даёт лучшее
  понимание: явно названа аналогией и потом переведена в инженерные понятия (эпизод 04 v5: монетка «10 орлов
  подряд → около тысячи бросков» → ведущие нули хэша), а не подменяет их по всему ролику. Подкреплено: эпизод 04
  v1.1 — «очень много странной терминологии, не инженерных понятий» (пользователь); рецензенты этого не ловили —
  tech-writer проверяет явно.
- **Правила серии — ориентир, а не запрет**: если отступление даёт лучшее понимание, его берём и пишем, почему.
  Решение пользователя 23.10: «не относись к запретам буквально».
- **Ролик обучающий, в развлекательном стиле — о собеседованиях не говорим** ни в голосе, ни в кадре.
  Подкреплено: прослушивание закадра эпизода 01 (пользователь: «щель», «табло, лампа», рваные фразы,
  нет переходов, «не надо про собеседование»).

## Ярлыки-термины
- Каждый акт получает ярлык (`d.term(...)`) — формальное имя проблемы/паттерна. Появляется на кадре,
  где механика уже показана (держит тест), живёт до конца акта.
- Ярлык: английский, ≤ 4 слов, не больше одного «·», без стрелок и скобок-пояснений, не повторяет
  то, что уже в кадре. Расшифровка — голосом диктора в том же кадре.
- Новые термины проверяет tech-expert до реализации: неточный термин хуже отсутствующего
  (в эпизоде 01 «fencing token» и «→ at-least-once» были бы неправдой).

## Правила пополняются по ходу работы
Формат: **утверждение** + чем подкреплено, цена вопроса. Устаревшее править на месте.
