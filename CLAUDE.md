# edugo

Короткие анимированные сцены с лёгким юмором, объясняющие темы Go и бэкенда (гонки, блокировки,
транзакции). Сцена = детерминированная симуляция + отрисовка в браузере (SVG).
Карта кода — `docs/architecture.md`, состояние серии — `docs/state.md` (в `master`), эпизода — `docs/episodes/NN-state.md`
(в его ветке), сценарии — `docs/episodes/`.

Команды: `npm run dev` (просмотр), `npm test` (vitest), `npm run check` (tsc), `npm run build`,
`npm run render` (mp4), `npm run narration` (закадр для правки), `npm run tokens` (расход токенов).
Удалённый репозиторий: `origin` = `git@github.com:rkata-hexlet/edugo.git`, ветка `master`.

## Для кого и как выпускаем
**Продукт — mp4-ролик для школы программирования, раз в неделю**; школа публикует его в своих
соцсетях, пользователь — в своём Telegram-канале (личный бренд). **Качество материала важнее
скорости и количества**: ролик уходит наружу под именем автора, переделать после публикации нельзя.
Готово = готовый mp4 (картинка, звук, голос; без субтитров — решение пользователя 21.10), проверенный просмотром целиком. Веб-плеер —
инструмент сборки и проверки, а не продукт. Подкреплено: решение пользователя 19.10.
**mp4 рендерю только по команде пользователя**, когда эпизод утверждён к выпуску; пока идут правки —
проверка только в браузере (`npm run dev`). Подкреплено: 19.10 — «зачем mp4, мы ещё править будем».

## Критерий качества эпизода
**Посторонний зритель понимает базу с первого просмотра, не напрягаясь**; термины и тонкости
ложатся поверх понятой базы. Пользователь смотрит эпизод не разбирая, а проверяя, «заходит» ли.
Проверяет `learning-designer`.

## Стиль серии — `docs/series-style.md`
**Перед работой со сценарием, закадром, подписями, репликами или ярлыками — прочитать
`docs/series-style.md`** (подача серии по эталону эпизода 01, текст в кадре, закадровый голос, ярлыки-термины).
Вынесено из этого файла 27.10: он читается на каждом ходу, а стиль нужен только в работе с текстом.
Самое главное, чтобы не промахнуться без файла:
- арка: знакомство с системой → хук → норма → кейсы от наивной попытки к верной; итог — повтор образов;
- текста в кадре минимум, постоянных индикаторов нет; картинка раньше термина;
- закадр — связный живой рассказ от «мы», с переходами от прошлого кадра, без телеграфного стиля и
  внутреннего жаргона; термины — как в профессии; о собеседованиях не говорим.

## Процесс эпизода
- **Ветки: эпизод — своя, общий код — своя.** `episode/NN-тема` — сценарий, сцена, дубли; в `master` после
  выпуска. Общий код (`engine/`, `kit/`, скрипты) — `refactor/…` или `engine/…` от `master`, вливается сразу,
  как только тесты зелёные и выпущенные эпизоды не изменились (эталон кадров или снимки); ветка эпизода потом
  подтягивает `master`. Иначе общий код застревает в ветке неготового эпизода. Решение пользователя 22.10;
  история до него (эпизод 02 в `master`) не переписывается.
- **Правила, чек-листы, агенты и список тем — тоже общий код**: `CLAUDE.md`, `.claude/agents/`, `docs/reviews/06-recurring-mistakes.md`,
  `docs/episodes/ideas.md` правлю в `master` (отдельной веткой, сразу), а не в ветке эпизода. Подкреплено 27.10:
  правила фаз и «ролик по теме» прожили три дня только в ветке 07 — в 08 и 09 их не было видно.
- **Состояние — в двух местах**: `docs/state.md` в `master` — список эпизодов (фаза, что дальше), порядок выпуска,
  общие уроки; журнал эпизода — `docs/episodes/NN-state.md` в его ветке. Сменилась фаза — строка в таблице `master`
  той же сессией. Решение пользователя 27.10 (копии общего журнала в восьми ветках расходились).
- **Ветка эпизода от ветки другого эпизода — только если нужен его код или сцена** (отсылка, мир); тогда выпуск по
  порядку цепочки (таблица в `docs/state.md`). Иначе — от `master`.
- **Темы и кейсы предлагаю от самых востребованных к редким**: насколько часто обычный бэкендер встречает это в
  работе. Редкое — в конец списка или в «отдельный эпизод». Решение пользователя 23.10.
- **Фазы эпизода — четыре; без указания пользователя делаю фазы 0 и 1 и останавливаюсь.**
  - **0. Сборка** — разборы tech-expert и scriptwriter, сценарий, MVP: все акты серыми фигурами, закадр, звук-черновик.
  - **1. Приёмка** — стоп: пользователь смотрит ролик и утверждает текст, раскадровку, повествование. Дальше без его
    слова не иду. Здесь не вылизываю: токены на полировку — только после утверждения сюжета.
  - **2. Шлифовка** — эпизод доводится целиком: цепочка текстов (tech-writer → tech-expert → learning-designer),
    отрисовка и анимация по motion-designer, звук по sound-designer, итоговая сверка tech-expert и мой проход по диффу. Итог
    фазы — **черновик**: готов всё, кроме голоса и mp4. «Оставим черновиком» = довести фазу 2 до конца.
  - **3. Выпуск** — дубли голоса пользователя (`npm run ep -- NN`) и mp4 по его команде; потом ветка — в `master`.
  Решение пользователя 24.10 (эпизод 07: «7 сюжет ты ещё не добил»; фазы — «если ничего не говорю, делаешь фазы 0 и 1»).
- **`/code-review` в этом проекте не предлагаю и не запускаю**: дорого по токенам, проект того не стоит. Перед коммитом —
  мой собственный проход по диффу (что сломано, что лишнее, что не покрыто тестом). Решение пользователя 27.10 («больно
  много эта команда жрёт токенов»); перекрывает общее правило «крупный дифф — предложить /code-review».
- **Каждый эпизод начинается с MVP**: все акты подряд, серые фигуры + подписи, без полировки.
  Показать пользователю → обсудить сюжет → только потом детали и анимация. Полировать до
  утверждения сюжета — пустая трата: акты переписываются.
- Сценарий живёт в `docs/episodes/NN-*.md` и обновляется после каждого обсуждения.
- **Закадр правит пользователь одним куском**: я выгружаю весь текст эпизода из `script.ts` в
  `docs/episodes/NN-narration.md` (`npm run narration`, строка = кадр с номером), пользователь
  правит, я разношу обратно в `script.ts` и сценарий и выгружаю файл заново (номера сдвигаются);
  смысл правок сверяет tech-expert, реплики — глазами на кадре. Решение пользователя 19.10.
- **Голос — дубли пользователя** (ADR-0004): пишет суфлёром `?record`, дубль привязан к тексту кадра.
  Правка закадра после записи — сказать пользователю, какие кадры перечитать (суфлёр начнёт с них).
  Синтез — только запасной для кадров без дубля и для MVP до записи. Решение пользователя 21.10; подкреплено
  после записи эпизода 01 — «понравилось, как записывали, так и будем делать».
- **Тексты идут цепочкой** scriptwriter (черновик) → tech-writer (стиль) → tech-expert (смысл) →
  learning-designer (восприятие). Смысл проверять после стиля: правка стиля после смысла ломала
  его (кадры 9, 14, 20 эпизода 01). Текст, переписанный пользователем или внешней моделью, — так
  же: стиль принимаем, смысл сверяет tech-expert, реплики — глазами на кадре. Подкреплено: живой
  закадр v5.1 принёс 8 смысловых огрехов (чужая строка под замком, «тут же», «ровно одно письмо»)
  и две реплики, наехавшие на шапку.
- Перед полировкой — план этапов по образцу `docs/plan-01-polish.md`; рецензентам показывать
  контактные листы кадров (`?capture` + headless Chrome), а не только код: по картинке они ловят
  реальные дефекты.

## Команда
| имя | модель | роль | когда зовём |
|---|---|---|---|
| `tech-expert` | opus | senior backend (Go, Postgres, распределёнка): техническая точность, где метафора врёт, пропуски для собеса | сценарий перед MVP; симуляция и подписи после MVP |
| `scriptwriter` | sonnet | сценарист-методист: хук, темп, юмор, понятность подписей, нарезка под Shorts | сценарий перед MVP (с вводными tech-expert); подписи кадров после MVP |
| `sound-designer` | sonnet | звукорежиссёр: словарь звуков событий, голоса персонажей, рецепты Web Audio | перед реализацией звука эпизода и после неё |
| `tech-writer` | sonnet | технический писатель: устоявшаяся терминология (англ./рус. как в профессии), связная живая речь, произносимость для синтеза | закадр и подписи после черновика scriptwriter, до проверки tech-expert |
| `learning-designer` | sonnet | методист по восприятию (Mayer, Sweller): поймёт ли посторонний базу с первого просмотра, перегрузка кадра, синхронность голоса и картинки, подсветка | после MVP с закадром и после крупных правок подачи |
| `motion-designer` | sonnet | моушн-дизайнер: визуальный язык серии, персонажи и предметы в примитивах SVG, анимация в такт голосу | после утверждения сюжета эпизода, перед полировкой отрисовки и после неё |

Opus — только tech-expert: его ошибка = зритель запомнит неправду (на эпизоде 01 он поймал три
технические ошибки сценария и одну в модели). Творческие роли — sonnet.

## На ревью проверять
- `scenes/*/sim.ts` детерминирован: без `Math.random`, `Date.now`, таймеров и DOM. Время — счётчик тиков.
- SQL/Go в подписях, SQL-панели и закадре соответствует тому, что реально делает симуляция (сцена не врёт).
- Сценарий `docs/episodes/NN-*.md` и `script.ts` сцены описывают одни и те же акты.
- `engine/contract.ts` — leaf, ничего не импортирует.
- Звук берётся **только из `World.events`**, не из сравнения кадров. Новое действие модели или
  глагол сценария, которое зритель должен услышать, пишет событие; стоп-кадры и «тихие» моменты
  выставляют флаги напрямую, без события (см. стоп-кадр гонки, хук).

## Визуал
- Цвета, кегли, иконки и виджеты — из `src/kit/` (тема серии), не свои в эпизоде. Эмодзи в кадре нет.
- Кегль ≥ 18 на кадре 1280×720; низ кадра ниже `SAFE_BOTTOM` (655) пуст — там подпись и субтитры
  плеера. Держит `view.test.ts`. Не влезает — убрать, а не уменьшить (motion-designer v4.3).
- **Субтитр диктора — одной строкой ниже `SAFE_BOTTOM`**: показывается кусками закадра (`phrases`,
  ≤ 64 знаков), в такт голосу. Две-пять строк целиком закрывали SQL-панель и табло (кадры FOR UPDATE и
  SKIP LOCKED v6). Проверять снимками всех кусков, а не одного кадра.
- Реплика Postgres в шапке — до ~37 знаков, иначе пузырь наезжает на значок кейса (кадры 30, 34
  v5.1). Тестом не держится — проверять снимком кадра.

## Экономия токенов
Главная статья расхода — не агенты, а длинная главная сессия: каждый ход заново читает весь контекст
(до 27.10 медиана 194k на ход, сессии по 300–700 ходов). Разбор 27.10; статистика — `npm run tokens`.
- **Сессия = одна подзадача, а не эпизод**: сценарий / MVP / цикл разборов / правки закадра / отрисовка /
  звук — каждый шаг своей сессией. Шаг закончен или контекст ≥ 120k (строка статуса желтеет) — записываю
  состояние в `docs/episodes/NN-state.md` и предлагаю `/clear`. Автосжатие на 200k — страховка, а не план.
- **Меньше ходов на действие**: `npm run check` вручную не гоняю — `tsc` запускает хук после каждой правки
  `.ts`; `npm test` — один раз после пачки правок. Независимые чтения — одним вызовом; файлы — фрагментом
  по строкам (`grep -n` → `sed -n`), а не целиком.
- **Кадры смотрю headless** (`?capture` + контактный лист), а не через Chrome MCP: загрузка его
  инструментов и снимки раздувают контекст. Chrome — когда нужно живое взаимодействие.
- **Разборы агентов пишутся в файл, мне — сводка**: агент сам кладёт полный разбор в
  `docs/reviews/NN-<роль>-<этап>.md` и возвращает ≤ 10 находок по убыванию важности. Повторная проверка —
  только по изменённым кадрам, со ссылкой на прошлый разбор.
- Статистика: `npm run tokens` (по неделям), `-- --by branch` (по эпизодам), `-- --by agent`,
  `-- --days 7`. Архив сводок — `~/.claude/token-stats/`, пополняется хуком в конце сессии (логи Claude Code
  живут ~30 дней). Метрики, за которыми следим: ctx мед (цель ≤ 100k), eq/ход, eq на эпизод.
- **Недельный отчёт** — crontab, понедельник 09:07 (`~/.claude/scripts/tokens-weekly.sh`) → `~/.claude/token-stats/reports/`.
  О новом отчёте сообщает хук `SessionStart`: говорю пользователю одной строкой и предлагаю разобрать.
